# GameStock

Внутренняя desktop-панель для поиска, анализа, покупки и перепродажи игровых аккаунтов.

Сейчас работает сбор объявлений с FunPay: коллектор ежедневно снимает категорию,
нормализует объявления, прогоняет их через предфильтр и складывает в Postgres.
AI-анализ и публикация на Eldorado — следующие этапы.

Авторизации нет: инструмент внутренний и поднимается локально.

## Стек

**Веб:** React · Vite · TypeScript · Tailwind CSS v4 · React Router · Lucide
**API:** Node · Fastify · Prisma · PostgreSQL · cheerio · node-cron

## Запуск

Нужен Postgres. База создаётся один раз:

```bash
createdb gamestock
cp apps/api/.env.example apps/api/.env   # поправить DATABASE_URL под своего пользователя
npm install
npm run db:push
```

Дальше — два процесса: API и веб.

```bash
npm run dev:api    # http://localhost:3001
npm run dev        # http://localhost:5173, /api проксируется на API
```

| Команда | Что делает |
| --- | --- |
| `npm run dev` | Дев-сервер веба |
| `npm run dev:api` | API с автоперезапуском |
| `npm run collect` | Разовый сбор с источника |
| `npm run collect -- --dry-run` | Сбор без записи в БД |
| `npm run analyze -- --limit=20` | AI-анализ объявлений, прошедших предфильтр |
| `npm run analyze -- --dry-run` | Показать, что будет проанализировано, без вызовов модели |
| `npm run build` | Типы + продакшн-сборка |
| `npm run typecheck` / `npm run lint` | Проверки |
| `npm run db:push` / `npm run db:studio` | Схема БД / просмотр данных |

Только desktop, минимальная рабочая ширина — 1280px.

## Состояние по этапам

| Этап | Статус |
| --- | --- |
| 1. Сбор с FunPay | **готово** — раздел «Маркетплейс» работает на живых данных |
| 2. AI-анализ и скоринг | **код готов**, ждёт `ANTHROPIC_API_KEY` — см. [docs/SCORING.md](docs/SCORING.md) |
| 3. Подтверждение и инвентарь | **готово** — решения оператора и покупки живут в БД |
| 4. Публикация на Eldorado | не начат — нужен `ELDORADO_API_KEY` |
| 5. Синхронизация актуальности | частично: исчезнувшие лоты уже помечаются |

Действия оператора пишутся в журнал `ActivityEvent` — он и питает ленту на «Обзоре»,
и служит аудит-следом: кто, что и когда решил.

На живых данных работают «Обзор», «Маркетплейс», «Топ аккаунтов» и «Инвентарь».
«Объявления» и «Продажи» пока на фикстурах — переедут на API вместе с подключением
Eldorado на этапах 4–5.

**Оплата не автоматизирована и не планируется:** покупку на площадке-источнике
оператор проводит сам, система только фиксирует факт и заводит позицию в инвентарь.

## Доменная модель

Ключевая идея — ничего не привязано к конкретной игре или площадке.

- `Game` — игра; реестр в `config/games.ts`. Специфичные для игры характеристики
  аккаунта живут в `GameAccount.gameData` (`types/games/*`), поэтому базовая сущность
  аккаунта остаётся игро-независимой.
- `Marketplace` — площадка с ролями `source` / `destination`. FunPay и Eldorado — обычные
  записи реестра в `config/marketplaces.ts`; в доменной модели нет полей вида `funpayPrice`.
- `GameAccount.source` — объявление на площадке-источнике, `InventoryItem.purchase` —
  покупка, `InventoryItem.resale` — план перепродажи (`recommendedPrice` от AI и
  `manualPrice` оператора), `InventoryItem.futureListings` — планируемые публикации.
- `MarketplaceListing` — объявление на площадке продажи, `Sale` — завершённая сделка.
- `AIAnalysis` — результат анализа: Quality Score, Deal Score, Risk Score, `analysisConfidence`;
  полнота извлечённых данных — `GameAccount.dataQuality`.

### Скоринг

- **Account Quality Score** — качество аккаунта вне зависимости от цены. Веса факторов
  описаны в `config/games.ts` (`scoringModel`).
- **Deal Score** — главный показатель: выгодность сделки. Учитывает качество, цену,
  рыночную оценку, сопоставимые объявления, ожидаемую маржу, риск передачи и надёжность
  продавца. Высокий Quality не означает высокий Deal.
- **Risk Score** — 0–100, чем выше, тем рискованнее сделка.

Пороговые значения и подписи — `config/scoring.ts`.

## Как расширять

| Задача | Что менять |
| --- | --- |
| Добавить игру | запись в `config/games.ts`, тип в `types/games/`, фикстура в `data/accounts/` |
| Добавить источник или площадку продажи | запись в `config/marketplaces.ts` |
| Подключить парсер / AI / Seller API | заменить загрузчики в `data/` на вызовы API — сигнатуры сущностей остаются прежними |
| Добавить раздел | страница в `pages/`, маршрут в `app/routes.tsx`, пункт в `config/navigation.ts` |

## Сбор данных

Коллектор ходит **только на страницы категорий** источника — ограничение зашито в код и
проверяется на каждом запросе. Один запрос в сутки, честный `User-Agent`, никакого обхода
защит. Подробности и открытые вопросы — в [docs/SOURCES.md](docs/SOURCES.md).

Повторный сбор идемпотентен: объявление опознаётся по паре «площадка + внешний id»,
изменения ловятся по хешу содержимого, пропавшие лоты помечаются датой исчезновения.
Решения, принятые дальше по конвейеру (одобрение, покупка), пересбором не затираются.

Атрибуты источника не считаются достоверными: площадка их не валидирует, и в корпусе
попадаются заведомо невозможные значения. Такие объявления отсеиваются до AI-анализа.

## Ограничения текущей версии

- Покупка, подготовка и публикация объявлений — mock-действия без внешних вызовов.
- Разделы «Инвентарь», «Объявления», «Продажи», «AI-анализ» пока на фикстурах.
- Раздел «Финансы» — заглушка с описанием следующего этапа.
- Оценки Quality / Deal / Risk считаются, но требуют ключа Claude API для извлечения
  характеристик из заголовков.
